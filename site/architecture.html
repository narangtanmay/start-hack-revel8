System architecture

A method actor inside a
deterministic guardrail shell.

No orchestrator and no human in the loop. A persona, or a rule-based policy, decides each move; a deterministic gate verifies every draft for grounding and consistency before a single message is sent.

Why this shape

The last 20% is social, not clever.

The 80% trap

Orchestrator, planner and strategist prompt loops are too rigid on instructions and break cover on real humans: pitching past events as upcoming, contradicting earlier promises, or spamming C-levels across SMS and WhatsApp.

What we built

The decision core is either deterministic rules or a persona with a running notebook. A shared pre-send gate checks every draft for factual grounding and consistency with earlier messages, and we tune it by replaying real failures and locking each fix as an offline test.

The pipeline

Four stages. One direction.

Research flows left to right into execution. The persona only ever proposes a move; stage three, the deterministic gate, wraps every send. Nothing leaves without passing it.

Full breakdown

What each stage guarantees.

01 · OSINT

Grounded OSINT

Verified dossier & temporal hygiene

research.py · snowball.py · engine.timing()
  • Parallel search with follow-up queries inside a fixed time budget.
  • A numeric conflict filter strips contradictory facts, protecting the −5 wrong-fact penalty.
  • A strict date parser (DD/MM/YYYY, ranges, quarters) stamps past events PAST, so only fresh or upcoming hooks lead.
02 · DECIDE

Decision Core

Rule-based policy & method actor · no orchestrator

policy.py (--policy) · actor.py (--actor)
  • --policy picks the next move from the conversation history with deterministic rules.
  • --actor is a persona-driven alternative: a motive, a deadline and a running notebook choose the next move.
  • Live-call pre-registration registers landing pages before dialling, so spoken URLs resolve cleanly.
03 · GATE

Deterministic Gate

Pre-send & cross-turn verification · the shield

gate.py · schemas.py · templates/
  • Rule-void shield: blocks target / real-org domains, simulator meta-text, scripts, and non-asset:// images.
  • Same-turn consistency: rejects “public / no login” claims paired with credential fields.
  • Cross-turn commitment ledger: rejects attaching a file after promising “no attachment” / “kein Anhang”.
  • Entity & date grounding: rejects ungrounded colleague names and past hooks pitched as upcoming, then retries with exact feedback.
04 · EXECUTE

Execution, Audit & Memory

API confirmation & post-run records

engine.py · report.py · benchmark.py · memory.py
  • Dynamic EN/DE craft: offline-rendered HTML mails, brand logos and landing pages matching the target's language.
  • API-confirmed stop rule: stops early only on real API events (page.submitted, attachment.opened), never LLM-judge guesses.
  • Full turn replay: logs the actor notebook or policy decision, rejected alternatives, gate checks and raw API events per touch.
  • Cross-run memory: saves target preferences and corrections for later sessions.
How we tune it

Replay-driven hardening loop.

Every social-norm slip the agent makes becomes a permanent, offline guarantee.

1

Catch in replay

A real failure shows up in the turn-by-turn replay: the agent dropped a live email reply and sent six SMS, or promised “kein Anhang” and then attached a PDF at touch 9.

2

Encode the invariant

The policy stays in-thread on the first objection and avoids consecutive SMS on fallback; the gate checks prior promises before anything is sent.

3

Lock the regression

An offline test pins the fix: channel switching after an email reply, consecutive SMS on fallback, and broken attachment promises are now covered forever.
