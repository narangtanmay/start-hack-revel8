The 80% Trap (What Breaks in Production)

Orchestrator + Planner + Strategist prompt loops are too rigid on instructions and break cover on real humans: pitching past events as upcoming, contradicting earlier promises, or spamming C-levels across SMS/WhatsApp.

Our Last-20% Approach (What We Built)

The decision core uses either deterministic rules or a persona with a running notebook. A shared pre-send gate checks drafts for factual grounding and consistency with earlier messages.

1 · Grounded OSINT

Verified Dossier & Temporal Hygiene

research.py · snowball.py · engine.timing()
  • Parallel search with follow-up queries within a fixed time budget.
  • Numeric conflict filter strips contradictory facts (protects −5 wrong-fact penalty).
  • Strict date parser (DD/MM/YYYY, ranges, quarters) stamps past events PAST so only fresh/upcoming hooks lead.
→
2 · Decision Core (No Orchestrator)

Rule-Based Policy & Method Actor

policy.py (--policy) · actor.py (--actor)
  • --policy uses rules to select the next move from the conversation history.
  • --actor is a persona-driven alternative under evaluation. It uses a motive, deadline, and running notebook to choose the next move.
  • Live-Call Pre-Registration: registers landing pages before dialling so spoken URLs resolve cleanly.
→
3 · Deterministic Shell (Outside Actor)

Pre-Send & Cross-Turn Verification Gate

gate.py · schemas.py · templates/
  • Rule-void shield: blocks target/real-org domains, simulator meta-text, scripts, non-asset:// images.
  • Same-turn consistency: rejects "public / no login" claims paired with credential fields.
  • Cross-turn commitment ledger: rejects attaching a file after promising "no attachment" / "kein Anhang".
  • Entity & date grounding: rejects ungrounded colleague names & past hooks pitched as upcoming; retries with exact feedback.
→
4 · Execution, Audit & Memory

API Confirmation & Post-Run Records

engine.py · report.py · benchmark.py · memory.py
  • Dynamic EN/DE craft: offline-rendered HTML mails, brand logos, & landing pages matching target language.
  • API-confirmed stop rule: stops early only on real API events (page.submitted, attachment.opened)—never LLM-judge guesses.
  • Full turn replay: logs actor notebook / policy decision, rejected alternatives, gate checks, and raw API events per touch.
  • Cross-run memory: saves target preferences and corrections after a run for use in later sessions.

Replay-Driven Social-Norm Hardening Loop (How We Tune the Last 20%)

1. Catch in Replay

Observed failure: Agent dropped a live email reply and sent 6× SMS, or promised "kein Anhang" then attached a PDF at T9.

2. Encode Invariant

Policy stays in-thread on the first objection and avoids consecutive SMS on fallback. The gate checks prior promises before sending.

3. Lock Regression

Offline tests cover channel switching after an email reply, consecutive SMS on fallback, and broken attachment promises.
