The model writes.
The code decides.

Every move the agent makes comes from deterministic code that we can replay from the run log. The language model only turns a decided move into words, and a gate checks those words before anything is sent. Every rule in the code was added after a real practice run went wrong; the change notices below list which run.

VIEW AOne touch, end to end

Only API events count. A reply that an LLM judge rates as promising is logged as an estimate and never as an incident.

VIEW BWhat the agent believes about the target

After every touch, target_state.py turns the API events and the target's own words into one reaction tag. No LLM is involved, so the same history always gives the same tag. The policy and the shadow twin read the tag on the next touch.

COLD

No contact yet, or nothing came back.

IGNORED

Touches sent with no reply. Silence counts as an answer.

ROUTED

The target sent us to someone else. Pivot only on the touch that got that reply.

ENGAGED_PULL

The target asks for more. Keep the thread and the channel.

FRICTION_BLOCK

The target refused a mechanism, which is then marked blocked.

LINK_OPENED_BOUNCE

The link was opened and nothing was submitted.

INCIDENT_CONFIRMED

The API recorded an incident. The run stops.
