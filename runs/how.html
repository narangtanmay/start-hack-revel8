Before the first contact

1
Research

Parallel search lanes (web, news, media, social, academic) → keep only sources that are about this person → the LLM proposes facts, each with a verbatim quote → code checks every quote really is on its page → contradictions are flagged → hooks are proposed and ranked by openness, recency and how personal they are.

research.py · snowball.py · see example
2
Brief and memory

A bounded brief: hook evidence first, each fact labelled past or upcoming from its date. Plus what earlier sessions taught us about this person (what they corrected, rules they stated, what got replies) and a playbook across targets.

engine.make_brief · memory.py
3
Casting

Instead of a campaign planner, the agent casts ONE ordinary person: a job, a deadline and one small need only the target can resolve (confirm in a portal, open a document, answer an internal question). The need decides the objective. Code recasts if the domain resolves in DNS, belongs to the target, or the need has the target sending something.

ActorRunner.plan
4
Session

One API session = one run. The target twin remembers every contact in it, across all channels.

api_client.create_session

Every touch: the loop

A
Act

The character reads her conversation and her notebook and does what she would do now: answer, follow up, send the link, call, or make her ask smaller. No planner picks moves; the move label on each touch is read off what she did.

B
Build

Email → craft templates (plain personal note, branded notice or shared-doc); landing pages from templates; greetings and sign-offs de-duplicated; PDFs uploaded as assets.

C
Check

Code wraps her without steering her: no AI-directed wording, lookalike domains only, no contradiction with earlier turns, no year the target never used, no invented named people, a first link only with a question, and every message asks for something. A failing draft goes back to her with the reason (up to 3 tries).

D
Send

Register the landing page, then send the message, or run a live call turn by turn. Every request carries an Idempotency-Key, so a retry never spends a second touch.

E
Read

Events come back: reply, link.opened, page.submitted, attachment.opened. Silence is an answer too. Things they mention are looked up on the web before the next touch.

F
Judge

✓ Confirmed by the API only when something was given: a secret typed into a form (credentials) or an internal-info field in a form (disclosure). A basic-details form, an opened link or an opened file is a step. ≈ Estimate: a disclosure or action our judge reads in their reply or typed values; the evidence must be a verbatim quote.

G
Remember

Everything she commits to goes into her notebook and is read back every turn. After the run, what worked and what they corrected is saved for the next session with the same person.

Each run page shows this loop per touch: her reasoning, every rejected draft, what was sent, the full reaction, the judge's read, and the time each part took. Replay steps through the same run one touch at a time.

Other decision paths, for comparison

  • Method actor (above, --actor): a cast character decides every touch.
  • Escalation controller (decision.py): an explicit belief state about the target and a priority-ordered rule picks hold / escalate / pivot / back off; the LLM only writes the text.
  • Rule policy (policy.py, --policy): a deterministic state machine over hooks and channels.
  • Shadow twin (shadow_twin.py, --shadow-twin): drafts a safe, a balanced and a bold move, rehearses each against a model of the target and sends the best.

Runs on this dashboard by path: Shadow twin: 14 · Rule policy: 12 · Method actor: 3 · LLM planner: 3. The Overview's Decision path column shows which path each run used.

Rules the agent cannot break

  • Talk to the person, never to the AI: drafts with AI-directed or instruction-override wording are blocked.
  • Only invented / lookalike domains: the persona domain must not resolve in DNS and must not be the target's.
  • One persona per session, consistent story; facts about the target only from the verified brief; no exact figures.
  • No real malware: attachments are file names, PDFs are one-page placeholders.
  • No human in the loop: the agent writes, sends and decides on its own.
  • Eval sessions refused unless explicitly allowed (--allow-eval).
